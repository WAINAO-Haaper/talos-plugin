# TALOS 像素小人场景系统（Pixel Bot Scenes）

> 目标：以首页「像素巡航小人」为基准，给除屈原外的每个页面设计
> **符合页面内容气质的专属动态场景 + 差异化布局**，终结「每页一个样」。
> 本文档是总纲；实施时在 `pages/<page>.md` 写单页覆盖细节。

---

## 0. 基准实现解剖（首页 `talos-pixel-patrol`）

**DOM**（`view.ts` Hero 构建器，全页面共享，CSS 按页显隐）：

```
.talos-pixel-patrol (aria-hidden)
├── .talos-pixel-track    虚线轨道，steps(4) 滚动
└── .talos-pixel-bot      像素机器人
    ├── .talos-pixel-shadow   投影，随步伐缩放
    ├── .talos-pixel-antenna  天线 + 顶端信号灯
    ├── .talos-pixel-head     头（border 像素框 + 发光）
    │   ├── .talos-pixel-eye.left/.right   眨眼 steps(1)
    │   └── .talos-pixel-mark              T 标
    └── .talos-pixel-body     身体 + box-shadow 双腿 steps(2) 踏步
```

**动效语法**：全部 `steps()` 帧动画（复古像素感的关键）、只动
transform/opacity、`image-rendering: pixelated`、颜色走 `--pixel-ac/-ac-2/-ink`
三个变量（各主题已覆盖）。

**性能纪律**（必须延续）：
- 纯 CSS 动画，合成器执行，**禁止 JS rAF 循环**；
- 数据驱动 = 渲染/刷新时设 CSS 变量或 data 属性，不动画帧里读数据；
- 每场景并发动画 ≤ 3 组；页面不可见时 CSS 动画自动不合成（Obsidian 单 leaf 天然满足）；
- `prefers-reduced-motion` → 每页一个**静态姿势**（pose），不是简单隐藏。

## 1. 共享机制设计

### 1.1 场景容器

Hero 中的 `.talos-pixel-patrol` 保留为小人的「舞台」。每页场景 = 同一 DOM 上
叠加**场景层**（场景道具）+ **姿势/配饰覆盖**：

```css
/* 页面场景 = 道具元素 + 小人姿态/配饰变化，全部 scope 在页面属性下 */
.talos-console[data-talos-page="inbox"] .talos-pixel-patrol { …场景布局… }
.talos-console[data-talos-page="inbox"] .talos-pixel-bot { …姿势/速度… }
.talos-console[data-talos-page="inbox"] .pixel-prop-parcel { …包裹道具… }
```

道具 DOM 由 Hero 构建器统一输出（每页 1–4 个 `.pixel-prop-*` 空 span，
非当前页 `display:none`），**不新增任何 JS 动画循环**。

### 1.2 数据驱动契约

渲染各页时，view.ts 往 patrol 容器写 CSS 变量（`setCssProps`）或 data 属性：

| 变量 | 来源数据 | 驱动什么 |
|---|---|---|
| `--scene-progress` | 0–1 进度（时间/发布率/闸门进度） | 小人轨道位置、闸门开合 |
| `--scene-count` | 计数（包裹/火箭/节点） | 道具显隐数量（cap 10） |
| `data-scene-tone` | good/warn/hot | 小人颜色、信号灯、步频 |

### 1.3 配饰层

小人本体不变，**配饰 = 头部/手部叠加 span**（像素安全帽、听诊器、扳手…），
用 `box-shadow` 像素画法，与身体同一语法。每页最多 1 件配饰，识别度优先。

## 2. 分页场景与布局设计

### 2.1 overview 总览（现状保持）

- **场景**：小人沿时间轴轨道行走，位置 = `--scene-progress`（当前时刻在
  08:30–22:00 骨架中的占比）；走过已完成时段步频快（动画时长缩短），
  到达**当前时段**停下做「挥手」帧动画；前方时段为虚影里程碑桩。
  收工（末时段过后）→ 小人走到终点坐下，头顶 `Zzz` 飘字。
- **数据**：当前时间；tasks.md 各时段完成态。

### 2.3 inbox 收件箱 ——「搬运工」⭐ 已布局，加场景

- **场景**：轨道上堆 `min(count,10)` 个像素包裹（`.pixel-prop-parcel`），
  小人从左把包裹推向右端「归档口」（推箱步态：身体前倾 = skew 几帧）；
  **>14d 的包裹带灰尘抖动**（translate 微抖 + 灰色调）。`count=0` →
  轨道清空，小人坐归档口边「喝咖啡」（杯子热气 steps 上升）——清空奖励态。

  `stopTriggered`（重估期）→ 发射架亮红灯，小人举「停」牌静止。

- **落地**（2026-07-20）：火箭 = `output.queue.length` cap 5，44–88% 均布；

### 2.5 projects 项目场景 ——「工地巡视」

- **数据**：P0 数量 → 集装箱数量（cap 3）。
- **落地**（2026-07-20，批次 3 ✅）：安全帽 = head 内 `.pixel-prop.helmet`

### 2.6 knowledge 知识枢纽 ——「星图园丁」

## 3. 反模式与纪律

- ❌ **JS 逐帧动画**（rAF/setInterval 驱动 DOM）——一切用 CSS steps()；
  一次性事件动画（火箭升空）用 animation + `animation-fill-mode`，播完即结束。
- ❌ 道具超过 10 个/页（像素风 = 少而准，超出用 cap + 「+N」徽章）。
- ❌ 遮挡信息：场景层高 ≤ Hero 区现有高度（~86px），不挤压数据面板。
- ❌ 每页都用同一种「走路」——步态必须有角色差异（推箱/乘车/弹跳/打盹）。
- ❌ reduced-motion 下直接消失——每页定义静态 pose（如搬运工=扶着包裹站立）。
- ❌ 主题失配：场景色必须走 `--pixel-ac/-ac-2/-ink` + 主题覆盖惯例，
  禁止场景内写死 hex。
- ❌ **零位移陷阱**（2026-07-20 实机）：数据驱动的走位终点可能与起点重合
  （如 daily 早于首时段 progress=0），动画在跑但小人原地不动——
  给走位变量加保底行程（`--bot-progress` ≥15%），真实数据变量与
  走位变量分离。
- ❌ **全静止警报态**（2026-07-20 实机）：异常/停止态把小人完全冻住
  会被读成「坏了」——警报改红色 + 道具示警（牌/灯），本体保留
  缓慢警觉起伏。
- ❌ **亚像素幅度**（2026-07-20 实机）：±1~2px 的呼吸/浮动在 58px 舞台上
  肉眼不可见——「低能量」场景的标志性动作幅度至少 4px 起，
  或配一个循环大动效（zzz 升起）兜底。

## 5. 跨页布局基线（2026-07-20 实机反馈定型，批次 3/4 必须沿用）

1. **module-hero 三区结构**：主卡 `grid-row:1/3` 跨两行（绝对主角）｜
   操作按钮右上｜统计副卡右下缩小（88px / 数字 20px）；小人舞台
   `grid-row:3` 全宽页脚、负 margin 贴 hero 下边框。
2. **舞台与首页同比例**：`--pixel-scale:1.55`、高 58px、bot top 4px；
   主色跟随该页 `--ac`。
3. **标题**：`h1.module-hero-title`，继承各主题 h1 字体（与首页同款）；
   hero 图标 = 导航 `.mark` 芯片语言（Bauhaus 主题为圆形黄底黑边徽章）。
4. **`--scene-progress` 语义按页隔离**：`syncPixelScene` 按 `activePage`
   分支写入，禁止无条件统一赋值。
5. **追加段断点重申**：任何后置覆盖必须在 1100px / 680px 断点内重申布局，
   否则大尺寸穿透窄屏。
