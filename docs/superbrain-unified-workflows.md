# Superbrain workflows in TALOS Plugin

Updated: 2026-09-28. Local candidate only; plugin ID `talos` remains 0.4.5.

The TALOS module command bar opens the vault's C01–C15 / M01–M10 catalog in the existing modal interaction. It reads `System/interface/talos-superbrain-ui/catalog.json` as data and `System/WORKFLOWS.md` as the workflow rule source. The kit installs no second Obsidian plugin. Markdown notes remain the user's source of facts; generated indexes, receipts, and task UI states are supporting records.

The existing 10-group / 32-action catalog provides native note capture, import, search, project updates, metadata checks, selected backup, and basic conversion. Module writes use their existing target/content preview. Confirmed local tools, native workflows, and scheduled jobs also enter the existing TALOS task runner for status and cancellation. The Superbrain detail modal opens mapped Markdown files, previews eight local deterministic tools, and can invoke the kit's Codex/Claude workflow bridge after explicit confirmation. M07 shows four optional jobs, each disabled until configured; M09 can verify a snapshot and preview isolated restoration to a new directory. The runner accepts fixed script names and argument forms, rejects symlinked tool paths, and compares script bytes with the installed package manifest before execution. The manifest lives in the same user-editable vault, so this catches accidental drift rather than proving resistance to coordinated tampering. A CLI receipt and current evidence files are checked; semantic correctness still needs user review.

Configured API providers use the existing TALOS ask/egress path to propose up to eight registered local module actions. The user can start a bounded sequence from the reviewed plan; each step opens the original editable module modal for file preview and explicit confirmation. TALOS task results are fed back before the next API proposal, duplicate actions and limits fail closed, and a completed workflow requires current file evidence plus a persisted in-vault receipt. The API proposal itself does not approve a write. Direct API chat retains its Plan-only tool policy.

The kit's `System/config.json` may specify `module_paths` for the 13 TALOS modules. On a new kit vault, TALOS imports this mapping before first-run schema detection. Existing saved user mappings take precedence. The kit default keeps `System/Identity`, `System/灵魂`, `System/模板`, `System/配置`, and `System/自动化` beneath `System/`. Users attaching an existing vault should check their mappings in TALOS settings and the kit config before importing or running tools.

Current limits: `flow.cycle` performs a single-file deterministic intake/index/memory/check subchain; the complete semantic C10 loop still uses the native Codex/Claude workflow. `system.repair` adds only missing empty frontmatter to ordinary Markdown, capped at 20 files, and leaves uncertain content for review. macOS Vision OCR is locally available; audio/video transcription requires explicit whisper.cpp, model and FFmpeg paths and has not passed a real engine test on this host. API suggestions now include these registered actions but still require original TALOS previews and approvals; a real API profile and user-result acceptance remain separate checks. CLI availability, Python, host permissions, system scheduling, external platform accounts, Windows execution, and full C/M semantic outcomes require separate observation. A modal entry or successful receipt is not a pass for a C/M result.
