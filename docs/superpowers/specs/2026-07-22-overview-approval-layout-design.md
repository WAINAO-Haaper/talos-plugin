# TALOS 总览审批区兼容性调整设计

日期：2026-07-22
状态：已确认并实施

## 目标

修复总览页“待审批按钮入口”越过左栏、被右侧统计墙遮挡的问题；将待审批和偏好审批改为并排的独立模块；适当压缩系统健康模块，并确保 Obsidian 窄分栏和移动宽度下无横向遮挡。

## 已确认需求

- 采用方案 A：审批区独立成行。
- 桌面宽度下，“待审批”位于左侧，“偏好审批”位于其右侧。
- 偏好审批提供“批准 / 拒绝”按钮，操作结果写回 `candidates.md`。
- 批准项从“待确认”移动到“已确认”；拒绝项移动到“已拒绝”。
- 写回记录包含日期和“TALOS 界面按钮”来源。
- 系统健康模块缩小，但保留健康分、数据源、刷新时间和断链信息。
- 不满意时可以只撤销本次修改，不影响工作区已有改动或真实 Vault 数据。

## 根因

当前 `.overview-ops-grid` 同时要求左栏至少 360px、右栏至少 620px，但响应式断点依据整个窗口宽度，而不是 Obsidian 内容分栏宽度。当窗口仍大于断点、实际内容区却已小于 980px 时，网格不能继续收缩。

审批条目内部的操作按钮组又是不可收缩的单行 flex。标题与“批准 / 拒绝 / 批准+模型”按钮的最小内容宽度相加后超过左栏，因此条目内容伸入右侧统计墙，形成截图中的遮挡。

## 布局设计

总览主体保留“运行态势 + 健康统计墙”的双列关系，但移除强制 360px + 620px 的组合最小宽度。系统健康卡的圆环、内边距和最小高度缩小，柱状统计区保留原有信息。

审批快捷区从“行动队列”卡内部移出，成为总览主体之后的独立两列区域：

1. 左卡：待审批，显示最多三项，保留批准、拒绝、批准+模型。
2. 右卡：偏好审批，显示最多三项，提供批准、拒绝。
3. 无项目时仍显示对应空状态，避免模块忽隐忽现造成页面跳动。

响应式规则以总览内容容器宽度为准：

- 宽内容区：待审批与偏好审批各占一列。
- 中等内容区：运行态势与统计墙上下排列；两个审批模块仍可并排时继续并排。
- 窄内容区：两个审批模块上下排列；按钮允许换行且始终留在卡片边界内。
- 移动宽度：健康卡改为单列，审批按钮使用可换行布局。

## 偏好审批数据流

新增独立的纯文本变换内核处理 `candidates.md`，不复用待审批提案的解析器，因为两种 Markdown 结构不同。

1. `collectCandidates` 从“待确认”分区读取完整候选文本，不再以 70 字截断值作为写回标识。
2. 用户点击批准或拒绝。
3. 操作层读取当前 `candidates.md` 最新内容。
4. 纯文本内核在“待确认”中精确定位该候选行。
5. 将原候选移入“已确认”或“已拒绝”；目标分区不存在时创建。
6. 在候选尾部追加日期、决策和“TALOS 界面按钮”记录。
7. 使用 `app.vault.modify` 单次写回，随后刷新总览数据并显示操作反馈。

重复标题按“待确认”分区中第一次精确匹配处理；完成后该行离开待确认区，因此同一次刷新中不会再次操作同一候选。

## 错误处理与安全

- 文件不存在：显示 Notice，不改变界面数据。
- 找不到“待确认”分区或目标候选：显示明确错误，不写文件。
- 目标分区不存在：在文档末尾创建标准二级标题。
- 写回失败：保留当前界面内容，交由现有刷新机制重新读取真实文件状态。
- 所有真实 Vault 写入仍只在用户点击按钮时发生；开发与测试使用纯字符串和临时数据，不修改真实 Vault。

## 测试设计

按测试驱动方式先增加失败测试，再实现：

- 批准候选：从待确认移除并进入已确认，包含日期和来源。
- 拒绝候选：从待确认移除并进入已拒绝。
- 目标分区已存在时追加到正确分区。
- 目标分区不存在时创建分区。
- 候选、分区或标题缺失时保持原文不变并返回错误。
- 完整长标题可以被准确写回，不依赖 UI 截断文本。
- 现有待审批测试继续通过。
- 运行 `npm test`、`npm run build`、`npm run lint`。
- 使用现有总览 QA 原型或本地静态验证，在桌面、中等分栏和移动宽度检查 `scrollWidth === clientWidth`，并确认两类按钮均未越界。

## 回滚方案

实施前执行只读状态检查，确认目标文件是否已有用户改动。随后在已被 `.gitignore` 排除的 `backups/` 下保存本次涉及文件的原始副本，并生成仅包含本次修改的补丁记录。

若用户要求撤销：

1. 仅恢复本次修改涉及且已备份的文件。
2. 删除本次新增的测试/内核文件。
3. 重新运行 build 和 lint，确认回滚后项目仍可构建。
4. 不执行 `git reset --hard`、`git checkout --` 或覆盖整个工作区。

本次回滚只覆盖插件源代码与样式，不回滚用户通过界面已经批准或拒绝的真实 Vault 数据；这类数据写入仍由用户主动点击触发。

## 预计涉及文件

- `src/view.ts`：拆分两类审批模块并接入偏好审批动作。
- `styles.talos.css`：独立审批网格、紧凑健康卡、容器级响应式与按钮换行。
- `src/candidate-actions.ts`：偏好候选纯文本变换内核。
- `src/actions.ts`：Vault 写回操作。
- `src/data/stats.ts`：保留候选完整标题。
- `tests/candidate-actions.test.ts`：候选批准/拒绝测试。
- `docs/design-qa.md`：补充本次响应式验证记录（验证完成后）。

不新增生产依赖，不修改插件清单、设置结构或真实 Vault。
