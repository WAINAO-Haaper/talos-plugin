# 项目场景页紧凑模块设计

日期：2026-07-22

## 问题

项目场景页复用通用 `.panel-grid` 的同排等高规则。左侧项目地图内容很长，右侧只有“场景索引”和“项目总 README”两个入口，却被强制拉伸到左侧整列高度；左右 1:1 分栏进一步放大了两个入口。

## 已选方案

采用“宽项目地图 + 窄紧凑入口列”：

- 桌面端左侧项目地图约占 70%，右侧入口列约占 30%。
- 右侧面板顶部对齐、按内容自然高度收缩，不参与左侧等高拉伸。
- “场景索引”和“项目总 README”继续上下排列，保持既有信息顺序与点击行为。
- 右侧每个入口使用紧凑行高和 padding，不填满剩余纵向空间。
- 左侧项目卡使用自适应列数：空间足够时 3 列，中等宽度 2 列，窄屏 1 列。
- 适度压缩项目卡的 padding、数字间距、进度区和最新文件间距，但不删除项目名、数量、优先级、任务进度或最新文件。

## 未选方案

- 保留 1:1 分栏只缩小行高：右侧仍过宽，主次关系不清晰。
- 把两个入口改成横向并排卡片：窄右栏可读性差，且与用户确认的上下排列不一致。
- 将入口移到项目地图上方：会改变页面信息架构，超出本次尺寸优化范围。

## 实现边界

- 在 `pageProjects` 的现有容器和两个 panel 上增加项目页专属 class。
- 仅在 `data-talos-page="projects"` 范围内覆盖网格、项目卡和入口行尺寸。
- 保留通用 `.panel-grid` 行为，健康、知识、输出等页面不受影响。
- 1100px 以下改为单列；入口面板位于项目地图之后。760px 以下保持单列项目卡，避免水平溢出。

## 验证

- 先增加结构测试，要求项目页专属 class 和非等高紧凑规则存在。
- 在约 1600、1024、390px 三档 TALOS 内容宽度检查模块宽高、文本完整性、点击入口、无横向溢出。
- 运行 Vitest、屈原 selftest、lint、生产构建与 diff 检查。
- 同步前备份 Obsidian 三个插件产物；同步后逐文件校验。

## 回滚

- 本次涉及的 `src/view.ts`、`styles.talos.css` 和测试文件单独备份。
- 安装目录继续使用同步前 `main.js`、`manifest.json`、`styles.css` 备份恢复，不修改 Vault 数据。
