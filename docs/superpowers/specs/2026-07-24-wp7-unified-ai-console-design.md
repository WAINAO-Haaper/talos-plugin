# TALOS WP7：统一 AI 控制台设计

日期：2026-07-24

状态：用户已确认设计

目标版本：正式 2.0.0

## 1. 背景

当前 `talos-plugin` 已经具备以下基础：

- 原生 Obsidian `ItemView` 控制台与十二个统计/业务页面；
- 内嵌 Claudian 2.0.25 的文字工作台；
- 屈原语音面板、持续语音、点击说话、STT 与 TTS；
- Claude API、Claude CLI、Codex 等 API/CLI 通道；
- 工具调用、文件差异、审批、执行和诊断能力。

WP7 不再重新实现一套 AI 运行时。需要解决的问题是：

1. TALOS 主控制台、Claudian 工作台和屈原语音入口仍然分散；
2. 大量统计卡片只能打开笔记或复制命令，缺少“直接执行”的完整反馈；
3. 审批、工具权限和执行记录存在多个入口，用户难以确认一次操作究竟是否执行；
4. 当前 API key 可落入插件普通 `data.json`，不符合正式 2.0.0 的凭证边界；
5. 十二个同级页面使导航密度偏高，用户打开插件后不容易判断下一步。

## 2. 目标

WP7 将现有能力重组为一个 TALOS 插件内的统一桌面控制台：

- 首页以“今天能做什么”为第一优先级，同时保留统计和九个模块入口；
- 文字对话和语音助手分别拥有独立页面与独立会话；
- 任何已配置的 API 或 CLI 大模型都可处理当前 Vault 的非密钥数据；
- 简单、固定范围、可恢复的操作允许点击按钮直接批准并执行；
- 批量修改、删除、身份变更、顶层结构、外部发布等高风险操作先提案，再由用户批准；
- 所有操作显示运行状态、结果、差异、审计和恢复信息；
- 插件升级、迁移和合成验收不修改九个客户模块；正式运行时，模型只有在符合动作审批规则后才能按用户请求修改库内内容。

正式 `2.0.0` 只有在 mock、真实 Provider、回归、升级和回滚验收全部通过后才能标记。

## 3. 非目标

WP7 不做以下工作：

- 不建立独立本地守护进程或第二套 Python AI 服务；
- 不重写 Claudian 会话引擎和屈原语音驱动；
- 不把 Ollama 作为 2.0 的默认主力，Ollama 保留到 2.1+；
- 不实现自动多模型辩论；2.0 只提供人工触发“请其他模型复核”；
- 不实现向量 RAG、完整通用工作流引擎或多格式预览器；
- 不因安装、升级或页面重组而移动、重命名或批量改写九个客户模块；
- 不自动向外部平台发布内容。

## 4. 信息架构

当前十二个同级导航入口收拢为六个一级入口。原有业务能力作为二级页面保留。

### 4.1 工作台

工作台是默认首页，采用“行动优先”布局，顺序固定为：

1. 今日建议操作；
2. 系统概览；
3. 九个模块入口。

首页不放置完整 AI 对话框。复杂任务通过顶部或导航中的“AI 对话”“语音助手”进入独立页面。

今日建议操作由统一动作注册表生成，不允许页面直接拼接不可追踪的命令字符串。每个操作必须展示：

- 操作名称与用途；
- 会读取或修改的范围；
- 风险级别；
- 预计耗时；
- 当前状态；
- 结果或失败原因；
- 查看记录与恢复入口。

### 4.2 AI 对话

AI 对话复用内嵌 Claudian 工作台，保留：

- 多标签和会话历史；
- 文件、选区、图片和外部上下文；
- Provider 选择与会话内切换；
- resume、fork、compact、rewind；
- 工具调用、差异预览、技能、MCP 与子代理；
- 人工触发“请其他模型复核”。

AI 对话拥有自己的会话历史，不继承语音会话内容。

回答默认只显示在会话中，不自动写入 Vault。用户明确要求保存，或模型提出保存建议后，写回遵循统一动作模型：

- 经过确认的知识结论优先写入 `30 洞察`；
- 成品、草稿和对外交付物优先写入 `70 输出`；
- 目标路径、文件名和差异在执行前可见；
- 写回风险由实际影响范围判定，不因来自 AI 对话而降低审批要求。

### 4.3 语音助手

语音助手保留为独立页面，用于产品展示和复杂任务交流，复用现有屈原语音模块及 TALOS 视觉体系。

语音页面同时支持：

- 默认持续语音对话；
- 用户随时打断 AI；
- 点击说话作为主动模式和故障降级；
- 实时字幕；
- 当前理解、任务状态、工具调用和审批提示；
- Provider 选择；
- 独立语音会话历史。

语音会话不继承文字对话内容。持续语音失败时保留已经形成的字幕和会话，明确提示用户切换到点击说话。

语音回答同样默认只保留在语音会话中。需要写回 `30 洞察`、`70 输出` 或其他模块时，必须进入与文字对话相同的动作审批流程。

### 4.4 工作流

工作流包含以下二级页面：

- 每日执行；
- 收件箱；
- 输出作战室；
- 项目场景。

### 4.5 知识资产

知识资产包含以下二级页面：

- 知识枢纽；
- 身份上下文；
- TALOS 产品。

### 4.6 系统中心

系统中心包含以下二级页面：

- 系统健康；
- 能力中心；
- 全库视图；
- 设置。

九个标准模块仍在首页展示为直接入口。导航调整只改变插件信息架构，不改变客户目录。

## 5. 统一动作模型

### 5.1 动作注册表

所有可点击执行的功能必须注册为明确动作。每项动作至少包含：

- `id`：稳定、唯一的动作标识；
- `label`：面向用户的名称；
- `description`：将要完成的事情；
- `risk`：A、B 或 C；
- `readScope`：允许读取的范围；
- `writeScope`：允许写入的范围；
- `executor`：实际执行入口；
- `timeout`：超时边界；
- `cancelable`：能否取消；
- `reversible`：能否恢复；
- `resultType`：预期结果类型。

页面只消费动作注册表，不自行决定审批规则。

### 5.2 风险级别

#### A 类：只读

示例：刷新统计、检索、打开内容、运行只读诊断。

- 点击后直接执行；
- 不弹确认框；
- 仍记录 Provider、读取范围和结果。

#### B 类：固定范围且可恢复

示例：生成晨报、运行系统自检、按既定规则整理收件箱、同步索引。

- 点击“批准并执行”即构成本次明确授权；
- 执行前创建恢复快照或等价恢复信息；
- 不再弹出第二个确认窗口；
- 超出注册范围时必须停止并升级为 C 类提案。

#### C 类：高风险

包括：

- 删除；
- 批量移动；
- 顶层结构调整；
- 身份与稳定规则修改；
- 超出固定范围的批量写入；
- 外部发布；
- 任意 shell、系统或外部命令执行；
- 其他不可恢复或影响不明确的操作。

C 类必须先展示：

- 计划执行的步骤；
- 影响文件与目录；
- 新增、修改、移动、删除数量；
- 关键差异；
- 是否可以恢复；
- 使用的 Provider。

只有用户点击“批准执行”后才能进入执行器。打开提案或查看差异不构成批准。

### 5.3 状态机

每个动作统一使用以下状态：

`可执行 → 排队 → 执行中 → 已完成 / 部分完成 / 已失败 / 已取消 / 已撤销`

按钮必须原位显示运行状态。切换页面不终止任务。所有页面共享可收起的“任务与执行记录”抽屉。

执行完成后至少显示：

- 开始与结束时间；
- 使用的 Provider；
- 已读取文件；
- 新增、修改、移动或删除结果；
- 错误；
- 审批凭据；
- 查看差异；
- 恢复或撤销入口。

部分执行失败时，执行器停止剩余步骤，分别列出已完成与未完成项目，避免盲目整批重跑。

## 6. 对话、语音与共同核心

文字对话和语音助手是两个前端界面，使用相同的底层服务：

1. Provider 中心；
2. Vault 检索和工具；
3. 风险与审批网关；
4. 任务执行器；
5. 差异和恢复服务；
6. 审计记录。

两类会话必须使用不同的会话命名空间，不能自动互相添加历史内容。统一任务记录只保存操作证据，不把另一界面的对话内容注入当前上下文。

### 6.1 文字请求数据流

`用户消息 → 上下文检索 → 密钥过滤 → Provider → 工具请求 → 风险判断 → 执行或提案 → 结果写回会话与任务记录`

### 6.2 语音请求数据流

`音频 → STT → 独立语音会话 → 上下文检索 → 密钥过滤 → Provider → TTS/工具请求 → 风险判断 → 执行或语音审批 → 结果写回语音会话与任务记录`

同一工具调用只能拥有一个执行标识。Provider 重试、换模型或恢复会话不得重复执行已经成功的工具步骤。

### 6.3 canonical `talos-ask`

WP7 新增 canonical 命令 `talos-ask`，作为不依赖具体页面的统一问答入口：

- Obsidian 文字对话、语音助手和命令面板调用同一问答服务；
- Claude/Codex 适配运行器通过 canonical registry 调用相同的检索、Provider、风险和写回规则；
- canonical 命令不得创建独立身份、记忆、审批或会话存储；
- 命令请求与执行结果使用 `.talos/command-requests/` 下的受管请求记录；
- 仅问答时不产生 Vault 写入；要求保存或执行工具时进入统一动作模型。

`talos-ask` 的运行行为以共享问答服务为唯一准绳，插件页面只负责输入、显示和审批交互。

## 7. Provider 与全库授权

### 7.1 Provider 形态

2.0 支持：

- Anthropic/Claude API；
- OpenAI 兼容 API，可配置端点、模型名和必要请求头；
- Claude CLI；
- Codex CLI；
- 通过统一适配器接入的其他 API 或 CLI Provider；
- mock Provider，用于确定性验收。

Provider 统一暴露对话、流式输出、取消、恢复、会话与能力描述。某个 Provider 不支持的能力必须在 UI 中明确禁用，不进行无声降级。

每个会话可以：

- 选择默认 Provider；
- 中途切换 Provider；
- fork 后选择其他 Provider；
- 人工发起其他模型复核。

切换 Provider 时保留会话文本，但必须记录切换点和新 Provider。已经执行的工具结果不得因切换而重复执行。

### 7.2 全库读取授权

授权粒度是“Provider + 当前 Vault”，不再按九个模块逐项勾选。

用户启用 Provider 时一次性确认：

> 允许该 Provider 读取当前 TALOS Vault 中除密钥和凭证之外的内容。

确认后，身份、候选信息、推断、项目、洞察、知识、记忆和输出都可以进入上下文。读取权限不等于写入权限；写操作仍由动作风险级别控制。

### 7.3 永久禁区

无论用户选择什么 Provider，以下内容不得进入模型上下文，也不得通过 Vault 工具读取：

- API key、token、cookie、登录凭证；
- `.env` 和明确的凭证文件；
- Obsidian SecretStorage 内容；
- 命中密钥模式的文本；
- Provider 配置中的敏感请求头。

阻断发生在工具和上下文组装层，不能只依赖提示词。

### 7.4 配置和凭证

`.talos/provider.json` 只保存非敏感配置：

- Provider ID 与显示名称；
- API 或 CLI 类型；
- 端点；
- 模型名；
- 能力标记；
- 默认项；
- SecretStorage 引用名称；
- 当前 Vault 授权状态。

API key 和 token 使用 Obsidian `SecretStorage`，普通插件设置仅保存 secret 名称，不保存 secret 值。该用法遵循 [Obsidian 官方 SecretStorage 指南](https://docs.obsidian.md/plugins/guides/secret-storage)。CLI Provider 使用其现有本机登录状态。

插件启动时必须检测 `SecretStorage` 能力。当前 Obsidian 版本不支持时，API Provider 保持禁用并提示升级；不允许回退到普通 `data.json` 明文存储。CLI Provider 在其登录状态有效时仍可使用。

旧版 `data.json` 中的明文 key 迁移流程为：

1. 检测旧字段；
2. 写入 SecretStorage；
3. 保存 secret 引用名称；
4. 验证 Provider 可用；
5. 删除旧明文字段；
6. 失败时保持旧配置不动并明确提示，不进行半迁移。

## 8. 视觉和交互约束

- 复用当前 TALOS 的颜色、卡片、导航、排版和主题变量；
- 不引入第二套组件库；
- 统计类组件可以重新排布，但沿用现有视觉语言；
- “查看”与“执行”必须使用不同文案、图标和按钮层级；
- 主操作按钮必须写成具体动作，如“批准并整理 6 项”，不能只写“运行”；
- 任务状态不能只通过颜色表达；
- 键盘用户可通过 Tab、Enter 和 Space 使用导航、动作和审批；
- 减少动态效果设置下停用非必要过渡；
- 窄窗口使用上下布局，但不得隐藏审批、风险或恢复信息。

## 9. 错误处理

### 9.1 Provider 错误

- 保留用户输入和已经组装的非敏感上下文引用；
- 显示 Provider 返回的可理解错误；
- 允许换模型重试；
- 不重复执行已成功的工具；
- 鉴权失败时只提示更新 SecretStorage 引用，不显示 key。

### 9.2 语音错误

- STT 或持续对话失败时保留字幕；
- 自动停止持续监听，提示切换点击说话；
- TTS 失败不影响文字结果和工具执行状态；
- 麦克风权限被拒绝时提供明确恢复说明。

### 9.3 Vault 写入错误

- 停止后续相关步骤；
- 保留已完成步骤与失败位置；
- 显示恢复点；
- 用户选择后才能继续、重试或撤销；
- 不允许用整批重跑掩盖部分成功状态。

## 10. 兼容与迁移

- 保留现有命令 ID，旧命令作为新页面或新动作的兼容入口；
- 保留现有目录映射和用户主题设置；
- 现有 Claudian 文字会话迁移到文字会话命名空间；
- 现有屈原语音历史迁移到语音命名空间；
- 导航变化不迁移或改名 Vault 目录；
- 升级前记录插件版本、配置版本和会话格式版本；
- 回滚时旧插件仍能读取旧字段或迁移前备份；
- 九个客户模块必须在仅安装/升级、不执行用户业务动作的前后通过内容和路径差异检查。

## 11. 验收

### 11.1 确定性 mock

必须覆盖：

- Provider 注册、能力检测、切换、取消和重试；
- 全库读取与密钥永久排除；
- A/B 类点击执行状态机；
- B 类越界自动升级为 C 类；
- C 类未经批准零写入；
- 提案、差异、批准、拒绝、取消、部分失败和撤销；
- AI 对话的检索、工具和写回；
- 语音独立会话、持续模式和点击说话降级；
- 文字与语音历史不互相注入；
- 同一工具调用的幂等执行；
- 设置页、SecretStorage 引用和旧 key 迁移。

### 11.2 插件回归

必须通过：

- 现有 Claudian 工作台能力测试；
- 屈原语音、自检和诊断测试；
- 插件 lint、类型检查和生产构建；
- 页面导航、窄屏、键盘和减少动态效果检查；
- 现有设置、路径映射、会话与命令兼容检查。

### 11.3 TALOS 2.0 回归

必须继续通过既有门禁：

- 943 项测试；
- checksums；
- 179 基线；
- accept 9/9；
- 隐私门；
- WP6 升级和回滚。

自动化和合成验收不得修改九个客户模块；测试写入只能进入可替换系统资产或隔离夹具。真实端到端验收使用隔离测试 Vault；若必须在客户 Vault 验收，写入前需单独审批，并在验收后恢复且提供差异证据。

### 11.4 真实验收

至少完成一次：

- 真实云端 Provider 全库问答；
- 低风险按钮一键执行；
- 高风险提案、差异查看和批准写入；
- 独立语音会话；
- Provider 切换或人工模型复核；
- 从 WP6 升级到 WP7，并回滚到升级前版本。

真实验收必须保存 Provider、时间、读取范围、修改范围、审批、恢复点和最终结果，不记录密钥值。

## 12. 发布门

只有以下条件同时满足，才能标记正式 `2.0.0`：

1. mock 验收全部通过；
2. 插件与 TALOS 2.0 回归全部通过；
3. 真实云端 Provider 端到端验收通过；
4. WP6 升级和回滚通过；
5. 仅安装、升级和回滚造成的九个客户模块差异为零；
6. API key 已从普通 `data.json` 迁移到 SecretStorage；
7. 验收文档、失败记录和恢复证据完整。

## 13. 设计结论

WP7 的实现本质是“融合与治理”，不是重建：

- 一个 TALOS 插件；
- 一个共享执行核心；
- 两个独立 AI 会话界面；
- 六个一级页面入口；
- 一个统一动作注册表；
- 一个统一风险网关；
- 一个统一任务与审计中心；
- 多种 API/CLI Provider；
- 整个 Vault 可供模型处理，密钥永久隔离；
- 简单任务一键完成，复杂与高风险任务提案后执行。
